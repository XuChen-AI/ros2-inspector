## 一、需求背景（v0.2 要解决什么）

v1 只能巡检 MCP server 所在的本机。真实部署中 ROS 常装在**无头板子 / 远程服务器 / docker 容器**里，用户需要 ssh 到目标机器才能查看。v0.2 让"遥控器"（MCP server）常驻用户本机，通过 ssh 指挥任意远端执行同样的只读查看命令，并让监测类工具输出语义结论而非原始流水账。

## 二、关键架构决策（评审定案）

| 决策点 | 选择 | 理由 / 备注 |
|--------|------|------------|
| 执行架构 | server 常驻本机 + ssh 包裹远端执行；**否决**"server 装到板子上"（不做、文档不提） | 板子未必有 Python≥3.10+外网；多目标切换只有遥控器在本地才成立 |
| ssh 实现 | **paramiko**（新增依赖） | 密码+密钥双认证都支持；纯 Python；与现有同步代码合拍 |
| 认证 | 每目标二选一：password / key（+可选 passphrase）；密码明文存配置文件，**不特殊设置文件权限**，工具结果**不打码**（用户明确豁免） | 用户接受明文；手动编辑配置文件的能力必须保留 |
| 目标切换 | 配置文件登记多目标 + 全部工具加可选 `target` 参数，不填=本地；文件热加载（mtime 检查），增删目标零重启 | 解决"频繁改配置"痛点；无配置文件时行为与 v0.1 完全一致 |
| 配置管理 | 语义化增删查：`add_target`/`remove_target`/`list_targets` 工具；配置文件**只由程序写** | 用户全程可碰不到文件；但手动编辑永远允许 |
| 防 AI 乱写 | 四道代码级围栏：①工具参数即固定字段（填表式，无自由文本入口）②逐字段硬校验（名字/地址/端口/路径…）③增删两步预览确认（confirm=False 出预览，confirm=True 才落盘）④统一序列化器，落盘格式定死 | 大模型给的配置必须规范 |
| 连接确认 | `check_target` 试连返回身份卡（主机名/系统/ROS 发行版/容器/描述）；约定 AI 每会话首次使用新目标前先调它给用户过目 | 靠 instructions+docstring 约定，不依赖 elicitation（部分客户端不支持）；宿主工具审批是第二道门 |
| 容器 | 目标可选 `container` 字段：远端容器=ssh→`docker exec`；本机容器=直接 `docker exec`（transport 与 wrapper 正交） | "板子/docker/远程主机/本地"四种部署全支持 |
| 体检工具 | `ros_install_info`/`machine_readiness` 改为走执行器的命令式实现，体检"当前 target 指向的机器" | 否则 AI 查远端时被本机结果误导 |
| 监测语义 | 同步窗口上限 15s→30s（客户端等待上限的硬天花板）；`get_topic_rate`/`sample_topic` 输出语义结论（稳定/断流/停发/内容是否变化）；**后台监听器不做**（留待将来） | 快路径毫秒级保持不动；跨位置综合判断由 AI 串联多次调用完成（v1 既定哲学） |
| 远端防孤儿 | 远端命令外包 `timeout -k 1 <T+slack>`；本地维持 Popen 超时+进程组强杀 | 杀本地 ssh 杀不死远端进程，必须远端自了断 |
| 统一执行路径 | 本地/容器/远端全部经**同一 snippet 构造器**（校验后的 token 经 shlex.quote 拼入 `bash -c`） | 单一路径少分支；snippet 由可信代码从已过围栏的 token 构造，无注入面 |

## 三、目标配置模型

文件：默认 `~/.config/ros2-inspector/targets.json`，启动参数 `--targets <path>` 可覆盖。

```json
{
  "targets": {
    "lab-board": {
      "description": "实验室小车主机",
      "host": "192.168.1.50",
      "port": 22,
      "username": "ubuntu",
      "auth": { "method": "password", "password": "***" },
      "container": null,
      "setup_file": null,
      "distro": null,
      "env": { "ROS_DOMAIN_ID": "42" }
    }
  }
}
```

字段校验规则（`targets.py` 单一来源，读取与写入共用）：

| 字段 | 规则 |
|------|------|
| name | `^[a-z][a-z0-9_-]{0,31}$`，且不得为保留名 `local` |
| description | 必填，≤100 字符任意文本（人话描述，给用户确认用） |
| host | 主机名/IPv4/IPv6 字符集 `[A-Za-z0-9.:_-]+`，≤253 |
| port | 1–65535，默认 22 |
| username | `^[A-Za-z_][A-Za-z0-9_.-]{0,63}$` |
| auth.method | `password`（password 1–128 字符）或 `key`（key_path 本机必须存在；passphrase 可选） |
| container | 可选，`^[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$` |
| setup_file | 可选，绝对路径、受限字符集（多发行版/overlay 时的逃生门） |
| distro | 可选，`^[a-z0-9]+$`（远端多发行版时指定，否则取字母序第一个并提示） |
| env | 可选 dict，键 `^[A-Z][A-Z0-9_]*$`，值 `^[\w./:+-]{0,120}$`（典型：ROS_DOMAIN_ID、RMW_IMPLEMENTATION） |
| 未知字段 | 一律拒绝（防止 AI 随手塞字段） |

热加载：每次解析目标前比对 mtime，变了就重读+重新校验；坏文件报错且不破坏旧缓存。

## 四、执行层改造

```
runner.py   run_ros2(args, timeout, target="local") / stream_ros2(...)  ← 全部工具的唯一出口（不变原则）
  ├─ targets.resolve(name)          → TargetConfig
  ├─ snippet 构造器                  → "source <setup>; export K=V; exec ros2 <quoted args>"
  ├─ LocalExecutor   本机：/bin/bash -c <snippet>，Popen 超时+进程组强杀（v1 机制）
  │                  +container → docker exec -i <ctr> bash -c <snippet>
  └─ SSHExecutor     remote.py：paramiko 连接（按目标缓存复用+断线重连），
                     外包 timeout -k 1 <T+2>；+container → timeout … docker exec -i <ctr> bash -c <snippet>
remote.py   paramiko 传输：exec 流式读取（deadline + 分隔符计数）、连接池、connect_timeout=10s
```

- 远端 ROS 探测：`bash -lc 'ls /opt/ros/*'` + `command -v ros2`，按目标缓存；`setup_file`/`distro` 配置可覆盖；
- 围栏四层**原样保留**：`_validate_args` 在包裹前执行，语义与 v1 完全一致；
- 审计日志加 `target` 字段；
- 超时：远程 connect +10s 预算，命令超时上限维持 30s（客户端硬上限）。

## 五、工具清单（13 → 17，全部只读）

| 工具 | 变化 |
|------|------|
| 13 个既有工具 | 全部加 `target: str = "local"`；docstring 补 target 说明 |
| `get_topic_rate` | 窗口 1–30s；输出 `samples[]` + `min/max/average_rate_hz` + `verdict`（"稳定 ~10Hz" / "断续：N 次超 2s 间隙" / "窗口内无数据"） |
| `sample_topic` | 窗口 1–30s；新增 `distinct_messages`（内容去重计数）+ `content_changed` + note（"内容恒定，疑似空转" / "内容持续变化"） |
| `ros_install_info` | 重写：`ls /opt/ros`、`command -v ros2`、`printenv ROS_*` 走执行器，指哪查哪 |
| `machine_readiness` | 重写：`/etc/os-release`、`uname`、`nproc`、`/proc/meminfo`、`df`、`ls /sys/class/net`、`getent hosts`、locale 全走执行器 |
| `list_targets` ★新 | 列出全部登记目标（名字/描述/transport/容器/缓存发行版），**不发起连接** |
| `check_target` ★新 | 试连返回身份卡：主机名、OS、ROS 发行版与 setup 路径、容器探测结果、描述；连接失败给明确原因 |
| `add_target` ★新 | 填表式参数；confirm=False 返回将写入的完整预览，confirm=True 校验+落盘（原子写） |
| `remove_target` ★新 | 同样两步预览确认；删除后该目标立即不可用 |

## 六、server 引导（instructions 与 docstring 的约定流程）

1. 用户提到"看板子/远端/容器"→ AI 先 `list_targets` 看登记清单；没有合适目标 → 询问用户地址与认证方式后 `add_target`（预览→用户确认→落盘）；
2. **每会话首次使用某远端目标前必须 `check_target`**，把身份卡亮给用户点头；
3. 之后照常用 13 个查看工具，带 `target` 参数；不填=本地；
4. 换目标=口头说一句，AI 换参数，不动配置。

## 七、测试与验证策略（重要边界）

- **开发期只做不碰环境的验证**：配置校验/读写往返/热加载单测、snippet 构造与引号正确性、围栏新用例（含 target 不存在/非法名）、既有 fence_tests 全绿、`--version` 与工具注册冒烟。**不发起任何真实 ssh、不碰 docker。**
- **端到端验证：等用户明确发起**。用户准备好环境（本机 docker 靶子或真板子）并告知连接信息后，才做 17 工具的远端端到端实测。
- 发布前：用户拿真实板子做一次实机验收。

## 八、发版

v0.2.0，走既定五步流程（uv version → CHANGELOG → commit+tag → uv build → uv publish）；pyproject 新增 `paramiko>=3.4`；README 补"远程巡检"章节；`.mcp.json` 不强制改动（targets 走默认路径）。

## 九、开发顺序

1. `targets.py`：schema/校验/读写/热加载 + 单测
2. `runner.py` 重构：snippet 构造器 + LocalExecutor（含容器）+ target 分发；fence_tests 扩展
3. `remote.py`：paramiko 传输
4. 13 个工具加 `target`；`rosenv.py` 命令式重写
5. `manage.py`：4 个管理工具（两步确认）
6. `topics.py`：30s 窗口 + 语义聚合
7. `server.py`：`--targets` 参数 + instructions 更新
8. 全部单测绿 + 注册冒烟 → 汇报，等用户发起端到端
